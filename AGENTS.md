# AGENTS.md — build guide for AI coding agents

Guidance for an AI agent helping someone build, run, or modify this repo. Humans:
see [`README.md`](README.md), [`SDK-SETUP.md`](SDK-SETUP.md), [`TESTING.md`](TESTING.md).

## What this is

**Vaults Bridge** — a hardware-backed password manager for the Foundation
Passport Prime, in two halves that ship together:

- **`/`** — a KeyOS (Rust + Slint) app that holds credentials sealed to the
  device and shows an on-device approval screen for every release.
- **`extension/`** — a Chromium MV3 extension that detects login forms, verifies
  the origin, and talks to Passport over WebUSB.

The KeyOS-free crypto/protocol core lives in `logic/` and is `cargo test`-able on
the host with no device.

## ⚠️ Can this be cloned-and-run today? Not by an outside dev yet.

Be honest with the user about this before they invest time. There are two build
paths and **neither is a clean external `git clone && run` yet**:

1. **Foundation SDK path (`foundation` CLI)** — the intended future. **Currently
   blocked by an SDK bug:** the SDK's bundled `lib/keyos/server/macro` opens with
   `#![feature(track_path)]`, an unstable Rust feature that has been removed from
   current toolchains (stable *and* the pinned `nightly-2025-09-11`). So
   `foundation sim` / `foundation build` fail on a clean compile of `server-macro`.
   Tracked with the Foundation SDK team.
2. **KeyOS monorepo path (`cargo xtask`)** — works today, but needs a **private**
   `Foundation-Devices/KeyOS-dev` checkout as a sibling dir `../KeyOS-dev2` (the
   app's `Cargo.toml` path-deps into it). Not available to external developers.

**The single change that unlocks external clone-and-run:** repoint `Cargo.toml`'s
`../KeyOS-dev2/...` path-deps at the SDK's bundled `lib/keyos` (what a clean SDK
port does), and land the SDK `track_path` fix. Until both are true, tell the user
this needs Foundation-internal access.

## Prerequisites

- Rust toolchain (managed by the SDK/monorepo `rust-toolchain.toml`).
- **Nix** (Determinate or upstream) — required for the Foundation SDK.
- A **Chromium-family** browser (Chrome/Brave/Edge/Arc) for the extension.
  WebUSB does **not** work in Safari or Firefox.
- For on-device work: a **Passport Prime dev unit** and the `passport-drive` MCP.

## Build & run

### A) Foundation SDK path (preferred, once unblocked)

```bash
foundation doctor          # verify the SDK env (this passes today)
foundation sim             # hosted simulator (currently fails: track_path, see above)
foundation sideload        # copy to a connected Prime — needs a signing identity first:
foundation cert gen        # only run if the user explicitly wants signing set up
```
Install/refresh the SDK from a KeyOS-dev checkout: `cd <keyos>/sdk && just reinstall`
(Nix build; needs GNU tar on macOS). If it fails on a `foundation-slint` hash
mismatch, the `foundationSlintHash` pin in `sdk/nix/maintainer-flake.nix` is stale.

### B) KeyOS monorepo path (works today, Foundation-internal)

Drop the app into a KeyOS-dev checkout at `apps/gui-app-passwords` (see
[`docs/KEYOS-PATCHES.md`](docs/KEYOS-PATCHES.md)), then:

```bash
cargo xtask check gui-app-passwords     # type-check for device + sim
just sim                                # hosted simulator

# Full flashable device image:
export AR_armv7a_unknown_xous_elf="arm-none-eabi-ar"       # macOS micro-ecc link fix
export RANLIB_armv7a_unknown_xous_elf="arm-none-eabi-ranlib"
cargo xtask build-all                   # bootloader+recovery+normal → boot.img
                                        # (build-all, NOT `just build`, if target/images is empty)
cargo xtask flash                       # SAM-BA; omit --switch if already in SAM-BA;
                                        # on macOS just retry on "Status … was 3"
```

End-to-end browser test: [`TESTING.md`](TESTING.md).

## Repo map

| Path | What |
|---|---|
| `logic/` | KeyOS-free core: `vaults-bridge-{core,protocol,keystore,import}`. `cargo test`-able. Start here for logic changes. |
| `src/` | KeyOS/Slint app shell: engine wiring, approval UI glue, keystore persistence, transports (`webusb` device / `websocket` sim). |
| `ui/` | Slint pages under `ui/pages/*`. **`ui/gen/**` is generated by `build.rs` — never hand-edit.** |
| `extension/` | Chromium WebUSB extension. `background.js` holds the origin-verification security gate. |
| `docs/` | Wire protocol, hardware notes, KeyOS integration patch. |
| `app-config.toml` / `manifest.toml` | New-SDK config vs legacy manifest. **Both currently present** — a clean port keeps `app-config.toml` and drops `manifest.toml`. |

## Conventions for agents

- **No em dashes** in prose you add here (house style).
- SPDX header on every new source file (`GPL-3.0-or-later`; MIT for SDK-side files).
- The crypto/protocol logic is host-testable — run `cargo test` in `logic/` before
  proposing changes there; you don't need a device.
- Don't run `foundation sideload`, `foundation logs`, or `foundation cert gen`
  unless the user is explicitly working with hardware or signing.
- No secrets in the repo; it's public. GPL-3.0-or-later.
